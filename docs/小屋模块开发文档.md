#### 2026年5月17日（第三轮）

**后端启动失败排查与修复**

| 问题 | 根因 | 修复 |
|------|------|------|
| `ECONNREFUSED` 代理错误（前端） | 后端容器未运行 | 修复后端启动失败 |
| `SchemaManagementException: wrong column type found [text], expecting [oid (CLOB)]` | `CabinEntity.stateData` 标注了 `@Lob`，Hibernate 验证时期望 PostgreSQL `oid` 类型，但 V10 迁移建表用的是 `text`。由于项目使用 Flyway 管理 schema，Hibernate 无需再做校验 | ① 删除 `@Lob`，改为 `@Column(name = "state_data", columnDefinition = "text")`；② `application.yml` 将 `ddl-auto: validate` 改为 `ddl-auto: none` |

**经验总结**：同时使用 Flyway + Hibernate 时，应始终设置 `ddl-auto: none`（或 `ddl-auto: validate`），但若 `@Lob` / `columnDefinition` 与实际 DDL 不匹配，`validate` 会导致启动失败。推荐统一使用 `none`，由 Flyway 单一负责 schema。

**Redis Lua CAS 核心逻辑**（`CabinService.java`）
```lua
local cur = redis.call('GET', KEYS[1])
if cur == false then cur = '0' end
if tostring(cur) ~= tostring(ARGV[1]) then return 0 end
redis.call('SET', KEYS[1], ARGV[2], 'EX', ARGV[4])
redis.call('SET', KEYS[2], ARGV[3], 'EX', ARGV[4])
return 1
```
- 返回 1 → 写入成功，更新 PostgreSQL
- 返回 0 → 版本冲突，HTTP 409 + 最新 state 返回前端

##### 后端实现

**新增文件**

| 文件 | 说明 |

| `backend/.../media/ImageGenController.java` | REST 控制器；`POST /api/v1/game/image/generate` 提交任务，`GET /api/v1/game/image/task/{taskId}` 查询状态 |

**DashScope API 调用流程**

```
1. POST https://dashscope.aliyuncs.com/api/v1/services/aigc/text2image/image-synthesis
   Header: Authorization: Bearer {DASHSCOPE_API_KEY}
   Header: X-DashScope-Async: enable
   Body: { model:"wanx-v1", input:{prompt}, parameters:{style:"<anime>", size:"1024*768", n:1} }
   → Response: output.task_id

2. GET https://dashscope.aliyuncs.com/api/v1/tasks/{task_id}
   → output.task_status: PENDING | RUNNING | SUCCEEDED | FAILED
   → SUCCEEDED 时: output.results[0].url
```

**Prompt 增强策略（buildPrompt）**

| type | 自动注入的引导词 |
|------|----------------|
| `cabin_bg` | post-apocalyptic cozy survival shelter interior, warm lantern light, vintage radio, lofi illustration style, warm amber tones, top-down perspective |
| `item` | single item icon, top-down view, transparent background, pixel art style, warm muted colors |

用户自定义词追加在引导词之后，优先级低于风格锚定词。

**Redis 缓存策略**

| Key 模式 | 说明 | TTL |
|----------|------|-----|
| `image:gen:{sha256(prompt)}` | 相同 prompt 的最终图片 URL | 7 天 |
| `image:task:{taskId}` | 任务完成后的图片 URL（taskId 维度） | 7 天 |

缓存命中时 `submitTask` 直接返回 `status=SUCCEEDED`，前端无需轮询。

##### 已知局限 / 后续改进方向

1. **wanx-v1 图片 URL 有效期约 24h**：生产环境应在 SUCCEEDED 后将图片下载并存入 OSS/MinIO，前端改用持久化 URL。
2. **物品图片未集成生成入口**：当前仅实现背景图生成；可在 Inspector 面板为单个物品加"🎨 生成图片"按钮。
3. **wanx-v1 style 参数**：当前固定 `<anime>`，可在前端提供风格选择器（写实 `<photo>`、水墨 `<chinese ink>` 等）。
4. **并发限流**：DashScope 有 QPS 限制，高并发场景需在 Service 层加队列或令牌桶。
