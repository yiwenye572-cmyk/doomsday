#### 2026年5月17日（第三轮）

**后端启动失败排查与修复**

| 问题 | 根因 | 修复 |
|------|------|------|
| `ECONNREFUSED` 代理错误（前端） | 后端容器未运行 | 修复后端启动失败 |
| `SchemaManagementException: wrong column type found [text], expecting [oid (CLOB)]` | `CabinEntity.stateData` 标注了 `@Lob`，Hibernate 验证时期望 PostgreSQL `oid` 类型，但 V10 迁移建表用的是 `text`。由于项目使用 Flyway 管理 schema，Hibernate 无需再做校验 | ① 删除 `@Lob`，改为 `@Column(name = "state_data", columnDefinition = "text")`；② `application.yml` 将 `ddl-auto: validate` 改为 `ddl-auto: none` |

**经验总结**：同时使用 Flyway + Hibernate 时，应始终设置 `ddl-auto: none`（或 `ddl-auto: validate`），但若 `@Lob` / `columnDefinition` 与实际 DDL 不匹配，`validate` 会导致启动失败。推荐统一使用 `none`，由 Flyway 单一负责 schema。

**Redis Lua CAS 核心逻辑**（`CabinService.java`）
```lua
local cur = redis.call('GET', KEYS[1])
if cur == false then cur = '0' end
if tostring(cur) ~= tostring(ARGV[1]) then return 0 end
redis.call('SET', KEYS[1], ARGV[2], 'EX', ARGV[4])
redis.call('SET', KEYS[2], ARGV[3], 'EX', ARGV[4])
return 1
```
- 返回 1 → 写入成功，更新 PostgreSQL
- 返回 0 → 版本冲突，HTTP 409 + 最新 state 返回前端
