# 末日小屋需求分析与开发计划

版本：1.0

作者：项目团队（为求职展示并准备用于面试演示）

日期：2026-05-17

---

## 一、目标与背景

目的：在现有“末日生存文字游戏平台”基础上新增“AI 个性化小屋”模块，将文字生成能力扩展为可视化、交互、长期化的“家园系统”，以增强项目在求职与面试中的含金量与工程深度。该模块要体现全栈工程能力（前端渲染/交互、后端并发控制、AI 联动、数据持久化与运维可观测）。

背景：当前项目已有 AgentHarness、三级记忆、工具调用等架构优势，但面试官常把文字生成归类为“调 API 玩具”。小屋模块可把这些技术点串联为一个能够演示工程难点与产品价值的子系统。

成功指标：
- 可演示的本地 Demo（拖拽摆放、床/窗交互、出门归来机制、导出快照）
- RAG 生成的物品叙事与窗外情景触发
- 并发一致性方案验证（演示冲突处理或压力测试数据）
- 1~2 分钟演示视频与系统架构图

---

## 二、范围与原则

约束与原则：
- 与现有技术栈兼容：前端 Vue3 + Vite，后端 Spring Boot 3，Redis + PostgreSQL + pgvector。避免大规模重构。 
- 以“工程化、可演示”为优先：功能应可复现、可测试、可量化。 
- 安全与合规：AI 生成内容需做安全检查与缓存，图片素材遵守版权要求。

范围（全面但分层）
- 核心交互（必需）：画布拖拽/吸附/碰撞、保存/导出、版本控制、床与窗户交互、出门/归来流程。 
- AI 功能（重要）：RAG 物品叙事、布局推荐器（Agent），窗外景色动态生成。 
- 工程化（必须）：Redis Lua CAS、异步持久化、监控埋点、回放/快照。 
- 可选扩展（预留）：多人协作、图像生成高质量资源、社交分享。

## 三、面向用户的功能清单（用户视角）

优先级：P0（核心）、P1（增强体验）、P2（扩展）

P0 - 基本交互
- 进入小屋并看到房间全景、ItemTray、Toolbar、Inspector。 
- 拖拽摆放：从托盘拖入或拖动房间内物品，放置自动吸附到格子或自由放置（配置项）。 
- 碰撞检测与放置提示：不能覆盖重要区域或其他锁定物品时显示反馈。 
- 保存/恢复：可手动保存或自动节流保存（节流+onUp强制提交）。 
- 导出/导入：导出 JSON 快照，支持导入恢复。 

P0 - 床与窗户（必需）
- 床（Bed）交互：躺下休息选择时长（短/中/长），恢复体力，推进游戏时间，可能触发梦境/回忆或随机事件。 
- 窗户（Window）交互：显示当前世界景色（根据 timeOfDay/worldState 渲染），点击查看详细窗外信息或触发远景事件，靠窗休息获得额外恢复效果。 

P1 - AI 与沉浸
- 点击物品查看“查看故事”按钮，触发 RAG+LLM 为物品生成来源叙事（异步任务，支持轮询或 websocket 回填）。 
- 布局推荐器：基于玩家行为或偏好生成初始布局方案（可被用户接受/拒绝）。 
- 待整理区：出门归来新获物品放入托盘，用户手动摆放后关联故事。 

P2 - 进阶与扩展
- 多设备/多人协作编辑（冲突处理/实时广播）。 
- 高质量图像生成（像素艺术自动生成 + spritesheet 管理）。 
- 社交分享（生成分享图片/可导出的快照 URL）。

## 四、前端组件与行为规范

组件一览（建议放在 `frontend/src/components/game/` 下）
- `CabinCanvas.vue`（像素风，基于 Canvas / Pixi.js）
- `CabinStage.vue`（极简风，基于 SVG / DOM）
- `ItemTray.vue`：待放/待整理物品列表，支持拖拽、分页、搜索
- `Inspector.vue`：物品详情面板，包含“查看故事”与操作（旋转/删除/锁定）
- `Toolbar.vue`：保存、导出、重置、切换风格、进入休息/出门操作
- `CabinDemoPage.vue`：演示页面，集成上面组件并能导出 JSON

交互细节
- 拖拽行为：使用 Pointer Events，local-first 渲染（即时），按节流规则异步提交后端（例如：300ms 限制 + onUp 强制提交）。
- 吸附规则：支持格子对齐（grid size configurable）与自由放置；旋转以 90° 或 15° 为步长（配置）。
- 碰撞检测：基于 AABB 简单包围盒做碰撞提示，复杂场景可采用 SAT。 
- 本地撤销：保存最近 N 次操作栈，可用于 Undo/Redo。 

视觉与 UX
- 像素风：`image-rendering: pixelated`，预留 spritesheet/atlas 加载接口。
- 极简风：SVG 可变色、可缩放、主题友好。

无障碍
- Inspector 提供键盘操作入口，支持键盘微调位置/旋转。

## 五、后端 API 设计（最小集与扩展）

核心 API（REST）

1. 获取小屋状态（恢复）
- GET /api/v1/game/sessions/{sessionId}/cabin
  - 返回：CabinState（含 version、timeOfDay、items[]）

2. 提交状态变更（原子）
- POST /api/v1/game/sessions/{sessionId}/cabin/update
  - 请求体：{ changes: Change[], expectedVersion: int, idempotencyKey?: string }
  - 响应：200 + newVersion 或 409 CONFLICT_VERSION（返回最新 state）

3. 出门携带
- POST /api/v1/game/sessions/{sessionId}/cabin/take
  - 请求体：{ itemIds: [string], idempotencyKey }
  - 业务：标记物品为 carried，生成快照，返回托盘状态

4. 归来（待整理）
- POST /api/v1/game/sessions/{sessionId}/cabin/return
  - 请求体：{ foundItems: Item[] }
  - 业务：把新物品放入待整理区，触发物品故事异步生成

5. 休息触发（时间推进）
- POST /api/v1/game/sessions/{sessionId}/cabin/rest
  - 请求体：{ durationHours: int, expectedVersion }
  - 业务：更新 playerState（stamina）、推进 gameTime、可能触发梦境/事件

6. 获取/请求物品故事
- GET /api/v1/game/sessions/{sessionId}/items/{itemId}/story
  - 若已生成返回 200 + story；若未生成返回 202 + taskId（后台 Worker 生成）

7. 获取窗外视图模板
- GET /api/v1/worlds/{worldId}/view?hour=HH
  - 返回窗外视图模板 id、描述、关联事件概率

安全与头部
- 所有写入需携带 `X-Trace-Id`、`Idempotency-Key`（可选），并受授权机制保护。

## 七、并发一致性与持久化策略（详细）

目标：支持前端本地即时响应，同时保证多端/多请求的最终一致性且避免 lost update。

策略要点：
- 前端 local-first：拖拽即时渲染；后端提交按节流策略。 
- 写时使用 `expectedVersion`：所有写操作带 expectedVersion，服务器用 Lua 脚本在 Redis 上做原子比较与替换：
  1) GET currentVersion
  2) if currentVersion != expectedVersion -> return 409 + latest state
  3) else apply changes -> version++ -> write Redis JSON -> push async persist

- 幂等键（Idempotency-Key）：避免客户端重试导致重复操作。 
- 异步持久化：Redis 为热态，成功写入 Redis 后异步将快照写入 PostgreSQL（session_history）和 GameDiary（按需）以降低写延迟。 
- 回滚/合并逻辑：前端收到 409 时提示并提供“刷新并合并/覆盖/放弃”选项，合并可为半自动（展示冲突项供用户选择）。

技术实现建议：
- Redis Lua 脚本实现 CAS 原子操作（示例在实现阶段提供）。
- StateCommitAgent 负责校验并发规则与记录审计日志。 
- 前端节流策略：300ms 最小间隔 + onUp 强制提交。

## 八、AI 模块设计（RAG / 推荐 / 生成）

1) 物品叙事（RAG）
- 流程：物品请求 -> 检查 cache -> 若无则向 `pgvector` 检索相关 EventCard/Lorebook 片段 -> 组装 prompt template -> 调用 LLM（DashScope）生成短叙事 -> 存储并回填。 
- 要点：使用模板化 prompt + few-shot 示例减少幻觉，限制输出长度并做内容安全过滤。 
- 异步优先：首次请求可以返回占位（202），生成完成用 websocket/轮询回填。 

2) 布局推荐器（Recommendation Agent）
- 输入：玩家行为特征（L0 窗口）、偏好标签、物品持有情况、世界状态
- 输出：推荐布局（items + positions + style）和置信度
- 可实现路线：规则引导的 Agent（阶段1）-> ML/CLustering based（阶段2）

3) 窗外场景生成
- 框架：WorldFactory 预生成若干窗外模板（按 worldVersion、hour、weather），存为 metadata；前端按 hour 请求并渲染。 
- 可选：在后期加入图像生成（文生图）用于高品质背景，但初期建议用可配置模板或渐进增强。

## 九、监控、测试与可观测性

监控项：LLM 调用延迟/失败率、Redis CAS 成功率、状态写入吞吐、前端保存失败率、导出次数。 

日志与指标：
- AgentMetricsStore（已有）扩展以记录：`cabin:update` 延迟/成功/冲突；`item:story` 任务耗时；`rest` 操作触发率。 

测试策略：
- 单元测试：前端组件交互，后端 Controller/Service 边界测试，Lua 脚本单元验证。 
- 集成测试：端到端场景（拖拽->提交->Redis->PG persist），自动化脚本模拟多客户端并行写入触发冲突。 
- 负载测试：模拟高频拖拽提交以验证 Redis Lua CAS 性能与 PG 写入吞吐。

## 十、部署与运维考虑

- Redis：建议 Cluster 或 Sentinel 配置以提高可用性。 
- PostgreSQL：读写分离、定期 VACUUM 与归档会话历史以控制表增长。 
- LLM：配置备用模型与 timeout，使用 RetryExecutor。 
- CDN/静态资源：spritesheet 与静态模板使用 CDN 缓存。 

---

## 十一、风险与缓解（汇总）

风险：LLM 成本/延迟、并发冲突、幻觉生成、图片版权、前端渲染性能。

缓解：异步生成与回填、Redis Lua CAS + expectedVersion、模板+检索减少幻觉、使用低分辨率占位与人工审核、渲染合批与懒加载。

## 十二、详细开发计划（任务分解与里程碑）

总体周期：6 周（可按需求缩放）

Week 0（准备与设计）
- 产物：本需求文档、API 规范草稿、前端组件接口定义、数据模型草案。
- 任务：确认 UI 风格（像素 vs 极简）、定义 grid size、定义节流策略（300ms）、Lua CAS 草案。

Week 1（前端骨架 + 后端基础）
- 产物：`CabinDemoPage`、`CabinCanvas`（基础拖拽/吸附/本地撤销）、`GET cabin` API
- 任务：实现基本画布拖拽、ItemTray、Inspector 协议；实现 GET 接口返回示例 state。

Week 2（并发控制 + 持久化）
- 产物：`POST /cabin/update`（Redis Lua CAS 实现）、版本冲突演示场景、PG 异步快照 Worker
- 任务：实现 Lua 脚本并集成到 `CabinService`，实现前端节流提交与冲突提示。

Week 3（床/窗/休息流程）
- 产物：`rest` 接口、窗外模板 API、床与窗 UI 行为、时间推进示例
- 任务：实现床休息触发、时间推进、窗外视图按 hour 获取与渲染逻辑。

Week 4（AI 集成 P0：RAG 物品叙事）
- 产物：物品故事异步任务 Worker、`GET item/story` 支持 202/200 流程
- 任务：实现 RAG 调用链（pgvector 检索 + prompt template + LLM 调用），生成缓存策略。

Week 5（AI 集成 P1：布局推荐器 + UX 优化）
- 产物：简单规则/统计驱动的 Recommendation Agent、接受/拒绝 UI、演示视频脚本
- 任务：实现 recommendation API，集成到新会话初始化流或用户设置中。

Week 6（测试、监控、演示材料）
- 产物：集成测试、负载验证报告、2 分钟演示视频、架构图与面试讲稿
- 任务：完成面试话术准备、生成关键代码片段（Lua CAS、RAG prompt、Agent 调用示例）、录制视频。

交付与验收标准（每周）
- 每周交付 demo 可运行分支（feature/cabin/*），并在 PR 中附上演示截图/录屏。 
- 验收：关键操作成功率 >= 95%，冲突场景能正确返回 409 并展示合并/刷新流程；RAG 叙事示例质量通过人工审核。
